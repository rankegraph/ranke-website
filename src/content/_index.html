Everything you keep, in one graph.

Why did we ship with that CVE? Which firmware ran on this device in March? The bytes are in a backup somewhere, and the backup cannot say. Here every answer traces back to its source.

What a backup keeps

Your data sits in mailboxes, repositories, photo libraries, chat histories and logs. Applications are discontinued and formats fall out of use, and a backup keeps the bytes without keeping what they meant or where they came from.

A Ranke-Graph takes all of it into one graph. Everything enters as a claim — a file, a commit, a message, a photograph — recorded whole, attributed to whoever added it, at a stated time, with edges to whatever it came from. Nothing is overwritten and nothing is deleted, so the archive only ever grows.

A language model trained on those documents cannot tell you which document a statement came from, or whether anyone ever wrote it. Here a claim cites what it was built from, and following those citations always ends at an original source. Whatever an agent answers, you can walk back to the record it rests on.

Today it holds git repositories

Snapshot a git repository

Import a repository, the full history or a single commit. Each file becomes a claim of its own, linked to the commit, and the commit to the repository. The snapshot restores byte-identical to the original.

Ask when a vulnerable dependency first entered, and the answer names the commit, the author and the moment, with the bytes to check it against.

Next

Email, GPS traces, browser history, CI build logs

Each of these needs an adapter: a small program that reads a source and turns it into claims. Every adapter widens the set of questions the archive can answer.

An agent can extend the graph as readily as read it. Its analysis runs on a branch of its own: it adds claims, cites the records it read, and leaves the sources untouched. Whoever reviews it later can see every record the analysis drew on.

What the structure guarantees

  • Verifiable Every record can be checked against the bytes it names, by anyone holding it.
  • Traceable A claim cites its sources before it can exist, and every path ends at an original record.
  • Simple A storage backend needs three functions, and an adapter is a small client that maps a source into claims.
  • Storage-agnostic The graph is content, and any store holds it: a filesystem, Postgres, Neo4j, Redis or S3, or a stack of them at once.
